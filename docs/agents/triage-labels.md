# Triage Labels

The omskills engineering skills use canonical triage roles. This file maps
those roles to the actual labels used in this repo's GitHub Issues.

## State Labels

| Canonical triage role | GitHub label      | Meaning                                 |
| --------------------- | ----------------- | --------------------------------------- |
| `needs-triage`        | `needs-triage`    | Maintainer needs to evaluate the issue  |
| `needs-info`          | `needs-info`      | Waiting on reporter or owner input      |
| `ready-for-agent`     | `ready-for-agent` | Fully specified for an agent to pick up |
| `ready-for-human`     | `ready-for-human` | Requires human implementation           |
| `wontfix`             | `wontfix`         | Will not be actioned                    |

Each triaged issue should have exactly one state label.

## Category Labels

| Canonical category | GitHub label  | Meaning                    |
| ------------------ | ------------- | -------------------------- |
| `bug`              | `bug`         | Something is broken        |
| `enhancement`      | `enhancement` | New feature or improvement |

Each triaged issue should have exactly one category label.

## Triage Comments

When a triage skill posts a comment to GitHub, the comment must start with:

```markdown
> *This was generated by AI during triage.*
```
